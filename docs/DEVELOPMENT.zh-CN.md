# 开发说明

*[English](DEVELOPMENT.md)* · 返回 [README](../README.zh-CN.md)。

## 构建和检查

需要 Xcode 或兼容的 Apple Swift 编译工具，以及钥匙串中可用的 Apple Development / Developer ID 签名身份，不依赖第三方软件包。仅有一个身份时自动选择；多个身份时用 `CODE_SIGN_IDENTITY` 指定证书 SHA-1。构建前退出正在运行的应用。

```sh
./scripts/test.sh
./scripts/build.sh
"dist/Duo Effect.app/Contents/MacOS/DuoEffect" --probe
"dist/Duo Effect.app/Contents/MacOS/DuoEffect" --self-check
```

构建脚本故意拒绝临时签名：那会让每次重新构建后已存储的屏幕录制授权失效。稳定证书签名可避免这一点。当前使用本机 Apple Development 证书签名，未做 Developer ID 公证。

直接从终端运行 `--self-check` 的权限结果属于启动它的终端上下文，不能作为图形应用已获授权的证据；请以应用窗口中的授权状态为准。

## 人工验收

授权屏幕录制后，检查：低于阈值时逐渐模糊，重新打开至阈值时完全清晰；移动窗口和播放普通视频时背景持续更新；暂停和退出恢复原画面；外接显示器保持正常；锁屏、睡眠和唤醒后无残留效果。

## 效果模型

画面固定在面板后方的空间中，面板是看它的视口。眼睛视为针孔：画面每个角沿眼到角的射线投影到面板平面上，`CIPerspectiveTransform` 把画面映射到这个目标四边形，转轴让底边保持不动。设眼睛坐标为 (x, y, z)（以屏幕高度为单位）、δ 为屏幕相对竖直方向的旋转角，画面顶边落在面板上距转轴 (y + u·(1 − y)) / cos δ 处，其中 u = (z − y·tan δ) / (z + tan δ·(1 − y)) 是射线穿越面板平面的比例。眼睛高于屏幕上沿时（坐姿），这个高度在屏幕一动就超过 1，画面顶行被投影到面板上方并裁掉：从合盖第一度起，顶部的光线就穿不过倾斜的面板。投影后的顶边宽度同时收窄为 u，所以黑色只出现在面板看向画面侧面之外的地方——这不是遮罩，而是确实到不了眼睛的光。眼睛的左右和高度偏移会平移和旋转投影，因此测得的坐姿位置有意义。缓动作用在旋转上而不是几何上：低于阈值时送入投影的 δ 本身在两度角带内做 smoothstep，因此每一帧仍是某个真实屏幕角度的精确投影，而视觉响应从静止开始（该角带同时吸收传感器一度的量化）。变暗把一个完整的合盖进度淡出与转动面板的朗伯亮度（cos δ）叠加，所以画面转开时比纯淡出更快变暗；一条随 sin δ 增强的折痕阴影压在转轴上方的短窄区域。模糊半径仍由合盖进度经纵向蒙版驱动。透视滑杆在平屏与本投影之间混合（100% 是物理正确的），它是观感控件而非校准。

投影不仅知道画面在哪，也知道转轴在哪。`LidGeometry` 用屏幕高度为单位描述上盖：有效显示区从转轴上方一段底部边框（约 6.5 mm）开始，显示表面在转轴前方约半个上盖厚度（约 4 mm），摄像头位于切进有效显示区的刘海内、菜单栏上方的顶行之下约 3 mm，并凹进玻璃之后约 1.5 mm。由于这个偏移，画面底行不再固定于面板底边：上盖向观看者合下时，面板下部会看向画面底边之外，留下一条随合盖加深而变宽的黑色区域。同一个偏移也把相对显示器测得的眼睛位置换算到投影使用的转轴坐标系。默认值由 Apple 公布的技术规格推算——16 英寸有效显示区为 3456×2234、254 ppi（高 223.4 mm），机身厚 16.8 mm；14 英寸为 3024×1964（高 196.4 mm），机身厚 15.5 mm——这些常量位于 `LidGeometry`，并按面板实测的有效高度换算，因此 14 英寸和 16 英寸上盖都能得到正确的屏幕高度单位。设置中把检测到的机型（`hw.model`，如“MacBook Pro 14-inch, 2024”）显示为预设来源；「高级覆盖」展开后提供开关和四个毫米输入框（转轴下沿、屏幕间距、摄像头内缩、摄像头凹陷），可填入手工测量的上盖尺寸，并可一键恢复检测值。眼睛位置以竖直屏幕平面（翻开 90°）为参考；投影时会把它旋转到冻结的画面平面——即清晰阈值处屏幕所在的平面，因此阈值不是 90° 时也保持一致。默认是居中坐姿：转轴上方 1.3 个屏幕高度、前方 1.6 个屏幕高度（约 50 厘米）；点「假定居中」会显式采用这个标称位置。点「校准」会把观看者在三维空间中的位置冻结下来：相机运行约一秒（至多 5 次 Vision 人脸检测，`VNDetectFaceLandmarksRequest`），`FaceGeometry.estimate` 把每次检测换算成相机坐标系中的位置（用已知脸宽估距，角度偏移取双眼特征点而不是位于鼻部的人脸框中心），`FaceGeometry.worldEye` 再用该帧实时的屏幕角度把它旋转到世界坐标系（补偿相机随屏幕上盖一起转动），取平均后持久化（`eyeX`/`eyeY`/`eyeZ`）。此后每次合盖都用这个冻结的世界坐标，相机在其余时间关闭。可选设置（默认关闭）会在每个开盖周期重测一次：重新打开超过 75° 后保持十秒，执行同样的单次测量。macOS 不提供相机视场角，距离按典型的 FaceTime 相机镜头（70°）估算；角度偏移是实测的。帧只在内存中，随即丢弃。

传感器以整数度上报，因此原始角度到达像素前经过两级抗锯齿：与速率无关的指数滤波平滑量化读数（时间常数 120 ms，跳变超过 45° 时直接吸附），并按实测角速度向前预判 60 ms（不超过最新读数，避免阶跃过冲），渲染器再在自己的帧时钟上以 30 ms 时间常数向滤波后的目标插值模糊、透视和变暗——远低于角度滤波的 120 ms，因此呈现本身几乎不增加延迟。传感器以 120 Hz 轮询。屏幕画面按面板的最高刷新率捕获（ProMotion 为 120 Hz，其他显示器为其上限）并以相同帧率呈现，实时内容与合盖过程都跟显示器同步。

第一次合盖靠预武装保持无缝：屏幕处于清晰阈值上方 15° 以内时，捕获流和覆盖窗口已经以完全透明运行，因此越过阈值时直接显示实时画面，而不是等 100–300 ms 冷启动捕获再以满强度弹入。显示是即时的——覆盖层从第一帧可见起就不透明（渲染图像带不透明黑底，已逐像素验证），因为任何窗口透明都会让实时屏幕透出来——合盖本身则通过上述两度旋转缓动从静止开始。重新打开越过阈值仍然立即隐藏覆盖层；离开阈值 2 秒后停止捕获，避免在折点附近悬停时一直占用捕获流。

- `./scripts/render-check.sh` 生成 `docs/effect-preview.png`，用合成画面验证图像处理链，不读取屏幕内容。
- `./scripts/settings-render.sh` 离屏渲染设置窗口的英文和中文版本到 `.build/settings-en.png` 和 `.build/settings-zh.png`，作为文案和排版检查；不涉及屏幕捕获和权限。控件没有强调色，因为只有活动应用的 key 窗口才会画出强调色，所以 `docs/settings-*.png` 是应用的真实截图。
- `./scripts/make-icon.sh` 从 `Resources/AppIcon.png` 重新生成 `Resources/AppIcon.icns`；换图标时替换那张 1024×1024 图再跑它。

## 流畅度检查

`./scripts/benchmark.sh` 对 3024×1964 合成画面比较旧位图输出与 Metal 输出。初次本机测量中位数分别约 12.9ms / 4.7ms（不代表端到端帧率）。`./scripts/metal-check.sh` 验证实际纹理上下方向。核心测试同时覆盖按时间插值和达到阈值立即清晰。

## 调试模式

Duo Effect 是菜单栏应用，没有控制台，突然退出时除了系统崩溃报告什么都留不下。在菜单栏菜单里选「开启调试日志」，或用 `--debug` 启动，生命周期事件会写入 `~/Library/Logs/Duo Effect/debug.log`（也可在「控制台」中按 `local.ruixiang.macbookduo` 子系统查看）。「显示调试日志…」会在访达中定位该文件。

日志记录捕获的启停、渲染器的创建与释放、效果开关及当时的角度和阈值、传感器与权限变化、睡眠唤醒挂起，以及错误。逐帧输出被刻意省略，只记录异常帧。文件超过 4 MB 自动轮转。
